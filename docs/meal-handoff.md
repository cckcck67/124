# 開發交接(員工餐 App)

換新的對話時,先讀這份文件,再看 [meal.md](meal.md)(使用說明、排菜規則、初始卡池)。
VR網頁播放器的交接是另一份:[HANDOFF.md](HANDOFF.md)。

## 1. 使用者與合作方式
- 使用者用**繁體中文**溝通,回覆也用繁體中文
- 習慣:**先討論,確認後才實作**。使用者說「可以開始實作 / 照這樣改」才動手
- 公司員工約 30 人,每天一餐員工餐,自己叫貨;叫貨都用 **LINE** 傳給供應商
- 目前**自己一個人用**(單機,資料存在手機)。沒問題後才考慮連線版:其他師傅也安裝 App、共用資料和庫存量
- 很在意**資料不能遺失**(不想重新輸入)

## 2. 版本與發佈流程
- App 在 `meal/` 資料夾(Android,WebView 載入內建網頁),applicationId `com.cck.mealplanner`,桌面名稱「員工餐」
- 開發分支:`claude/employee-meal-app-planning-suyv18`(**還沒合併到 main**)
- GitHub Actions(`.github/workflows/build.yml`)編譯 → 發佈到 Releases 的 **`meal-latest`**(`MealPlanner.apk`),版本號 `1.0.N`
- 注意:這個分支 push 之後 Actions **沒有自動開始**,要手動觸發 `build.yml`(workflow_dispatch,選這個分支)
- 目前最新:**1.0.97**(主菜三選二、自己輸入菜名、批次新增、打字搜尋食材)
- 下載:https://github.com/cckcck67/124/releases/download/meal-latest/MealPlanner.apk
- **更新一定要覆蓋安裝,不要先解除安裝**(解除安裝會刪掉手機裡的資料)。和其他 App 用同一把簽章(`app/vrweb.keystore`)

## 3. 架構與檔案
| 檔案 | 內容 |
|---|---|
| `meal/src/main/assets/index.html` | 畫面:今日、菜單、叫貨、卡池、更多(品項、歷史、設定、備份) |
| `meal/src/main/assets/logic.js` | 核心邏輯(沒有畫面):抽卡、搭配檢查、菜商批次、用量計算、叫貨單比對、批次新增解析、舊資料升級 `migrate()`。**檔案開頭有完整的存檔格式說明** |
| `meal/src/main/assets/seed.js` | 初始資料:品項(依菜商原單)、初始卡池 95 道、預設設定 |
| `meal/src/main/java/com/cck/mealplanner/MainActivity.kt` | 存檔 `meal.json`、打開 App 時留上次的資料 `meal.prev.json`、剪貼簿、傳到 LINE、返回鍵 |
| `tools/meal_test.js` | 核心邏輯測試 15 項(CI 每次編譯前跑) |
| `tools/check_pages.py` | CI 檢查內建網頁和 .js 語法(三個 App 共用) |
| `docs/meal.md` | 給使用者看的完整說明 |

## 4. 已定案的規則
**菜單**
- 一次規劃 **7 天,從今天開始往後**(不固定星期幾開始)
- 先全部排成飯菜日,使用者再自己選 2~3 天改成**非飯菜日**(日期不固定:人少或有重要工作時)
- **飯菜日 = 主菜 2 道(豬 / 雞 / 魚三選二,不同種類)+ 蔬菜 2 道 + 蛋 1 道**;不含湯(有簡單的湯和飲料,不納入)
- 非飯菜日:獨立卡池(水餃、土魠魚羹、什錦炒麵、南瓜米粉、清粥小菜、皮蛋瘦肉粥…),預設 1 道
- 類別依**主體食材**:只有豬、雞、魚為主的算主菜;南瓜燒肉片這類肉片只是配料的算蔬菜;其他(豆腐、菇、筍…)都算蔬菜
- 卡片狀態:常用 / 輪替(自動抽)、候選(只能手動選,沒做過的菜)、停用(不出現,排過的菜只能停用不能刪)
- 修改方式:換一道(隨機)、手動選、用已叫貨的食材換菜、**自己輸入菜名**(外購的烤鴨、油雞,不列入叫貨)、鎖定
- 抽卡硬規則:魚每天最多 1、炸物最多 1、同種肉最多 1、主體食材不重複、常用 7 天 / 輪替 14 天 / 非飯菜日 10 天內不重複(設定都可改)
- 提醒(軟規則):深色醬汁太多、滷燒燉太多、口味重複、沒有綠色青菜、葉菜排在送貨後第 2、3 天

**叫貨**
- 人數固定以 **30 人**估算(員工有時自備或吃素,不逐日設定)
- 用量 = 30 人份**原料重量**(台斤,1 斤 = 600 克;一般蔬菜約 3 斤、易縮水約 4 斤);依叫貨級距無條件進位
- **菜商**:星期一、三、六叫,隔天送;一叫 → 二、三;三叫 → 四、五、六(三天量);六叫 → 日、一(星期一菜商休息不送)
- **豬肉商、雞肉商**:一週叫 1~2 次,日期不固定,使用者自己選日期區間(3~4 天量),單位台斤
- **庫存品**(雞蛋、冷凍魚、土魠魚塊、冷凍水餃、米粉…)不叫貨;菜商可代買冷凍貨
- 菜單改了叫貨單**自動跟著變**:未叫貨的自動更新;已叫貨的列出「需追加 / 用不到」;系統估算和手動改的量分開存
- 輸出:叫貨單複製或傳到 LINE(用供應商原始品名);**每週菜單報告只要菜名**(給員工看)

## 5. 已決定不做 / 已移除的事
- 湯品卡池:不需要
- 逐日設定人數:不需要(固定 30 人估算)
- 料理的「注意事項」「備註」:使用者要求刪除(資料欄位保留,畫面不顯示)
- 今日頁的「今天用到的庫存品」:使用者要求刪除
- 菜單頁右上的「週報」按鈕:和「複製本週菜單」重複,已刪除
- 第一階段不做:供應商品名對應表、價格與成本、員工接受度紀錄、Excel 匯出

## 6. 待確認 / 待辦
- **用量全部是建議值**,要使用者實際使用後回報再調整
- 初始卡池的肉類菜都先標「常用」;使用者沒做過的要改成「候選」
- 品名待確認(App 裡有「待確認」標記):豆菜(綠豆芽?)、杏菜苗、冬而、青龍、水血、馬薯(和洋芋同一種?)、豆干(原單只有豆干絲)、白北魚(實際魚種)
- 分支還沒合併到 main
- 之後的階段:
  - 連線版:其他師傅也安裝 App、共用資料和庫存量
  - 價格與成本(菜商價格單已有手寫單價)、員工接受度與剩菜紀錄、Excel 匯出
  - AI 建議新菜色(只加入「候選」,實際做過才改常用)

## 7. 資料安全(改程式時要遵守)
- 存檔格式改變時,**一定要在 `logic.js` 的 `migrate()` 補上舊資料的升級**,不能讓舊資料讀不出來而變成初始資料
- 格子數改變(例如主菜 3 → 2)時,鎖定的菜和自己輸入的菜要搬到新格子(`drawDay` 已處理)
- MainActivity 打開時把 `meal.json` 複製成 `meal.prev.json`(只在內容是正確 JSON 時才複製);存檔讀不出來時畫面改讀這份
- 使用者也可以「更多 → 備份 / 還原」複製整份資料

## 8. 開發時的檢查方式
- 本機沒有 Android SDK,Kotlin 無法在本機編譯;靠 GitHub Actions 編譯和 Robolectric 啟動測試
- `node --test tools/meal_test.js`:核心邏輯
- `python3 tools/check_pages.py`:網頁和 .js 語法
- 畫面:用 Playwright + Chromium(`/opt/node-tools/node_modules/playwright`)打開 `meal/src/main/assets/index.html` 點一遍、截圖檢查
- 改完要用繁體中文說明改了什麼、使用者要怎麼在手機上測試
