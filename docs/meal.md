# 員工餐 App 使用說明

員工餐的菜單抽卡、搭配檢查、食材用量和叫貨單。和 VR網頁播放器、整人聊天是不同的 App,可以同時安裝。

- 下載:Releases 中「員工餐」的 [`MealPlanner.apk`](https://github.com/cckcck67/124/releases/download/meal-latest/MealPlanner.apk)
- 新版直接安裝覆蓋即可,卡池、菜單、叫貨紀錄都會保留
- 資料只存在這支手機裡(第一版自己使用);換手機用「更多 → 備份 / 還原」

## 每週流程

| 時間 | 做什麼 |
|---|---|
| 開始規劃時 | 「菜單」→ 🎲 抽一週(從今天往後 7 天)→ 不滿意的菜點菜名換掉 → 選 2~3 天改成非飯菜日 |
| 菜單確定 | 「複製本週菜單」→ 貼給員工(只有菜名) |
| 菜商叫貨日(一、三、六) | 首頁會提醒「今天要叫菜」→ 打開叫貨單 → 傳到 LINE → 標記已叫貨 |
| 豬肉、雞肉 | 「叫貨」→ 產生叫貨單 → 選要涵蓋的日期(一次三、四天)→ 傳到 LINE |
| 每天 | 「今日」看今天要做的菜、食材用量和注意事項 |
| 有變故 | 「菜單」點菜名 → 換一道 / 手動選 / 用已叫貨的食材換菜 → 叫貨頁會自動列出要追加或用不到的量 |

## 畫面

### 今日
- 今天的菜、每道菜的食材和用量(依設定的人數換算)、注意事項(葉菜最後炒、炸物晚一點炸、魚刺…)
- 明天的菜單預覽、今天用到的庫存品
- 提醒:今天要叫菜、肉還沒叫、菜單改過要確認的叫貨品項
- 右上「複製」= 今天的菜名

### 菜單
- **🎲 抽一週**:從今天往後 7 天,每天重抽沒鎖定的菜(飯菜日 / 非飯菜日不變)
- **每天右上 🎲**:整天重抽(鎖定的菜保留)
- **飯菜日 ▾**:改成非飯菜日(或改回來),那天整天換成另一個卡池重抽
- **點菜名**:
  - 🎲 換一道:隨機換一道符合規則的菜,其他菜不動
  - ✋ 手動選擇:從卡池挑(候選菜也可以選;不符合規則的會說明原因,仍然可以選)
  - 🧺 用已叫貨的食材換菜:只列出這批已叫貨食材做得出來的菜(叫過貨才會出現)
  - 🔒 鎖定、看這道菜的食材 / 編輯
- **🔒 / 🔓**:鎖定的菜在任何重抽都不會被換掉
- 每天下方會顯示搭配提醒(⚠)

### 叫貨
- **菜商**:依叫貨排程自動分批,每批顯示叫貨日、送貨日、涵蓋哪幾天
- **豬肉商、雞肉商**:「＋ 產生叫貨單」自己選日期區間;已經叫過的日期會自動跳過,沒叫到的日期會提醒
- **庫存品用量**:雞蛋、冷凍魚、冷凍水餃、米粉等不列入叫貨,只顯示這 7 天用量;不夠時在菜商叫貨單「＋ 加品項」請菜商代買
- 叫貨單裡:
  - 數量 = 系統依菜單估算(同一食材跨菜色、跨日期彙總,依叫貨級距進位);點品項可以改,系統估算和手動的量分開保存
  - 點品項可以看是哪幾天、哪幾道菜用到的
  - 📋 複製 / 傳到 LINE(用菜商原始品名,和對方的單子一樣)→ 標記已叫貨 → 到貨後標記已到貨
  - 已叫貨的品項可以標記缺貨,會提示影響到哪些菜

### 叫貨單自動檢查
菜單一改,叫貨單就跟著變,不需要按重新計算:

| 叫貨單狀態 | 菜單改了之後 |
|---|---|
| 未叫貨 | 數量自動更新;手動改過的品項會提示「系統估算變成 X」,可以採用或保留 |
| 已叫貨 / 已到貨 | 不改已叫的量,列出「需追加」(可以複製追加單、傳到 LINE)和「用不到」的品項 |
| 複製之後菜單又改 | 提示「上次複製之後有更新,請重新複製」 |

底下「叫貨」圖示上的紅色數字 = 需要確認的品項數。

### 卡池
- 依類別(豬肉 / 雞肉 / 魚 / 蔬菜 / 蛋 / 非飯菜日)和狀態篩選、搜尋菜名或食材
- 新增、修改、複製成新料理、刪除(排過菜單的只能停用,保留歷史紀錄)
- 每道菜:類別、狀態、食材和 30 人份用量、主體食材、烹調方式、醬色、口味、注意事項、備註

### 更多
- **品項資料庫**:原始品名(叫貨單用)、標準名稱(畫面顯示)、向誰叫貨、單位、叫貨級距、耐放度、綠色青菜、待確認
- **歷史紀錄**:過去的菜單和叫貨單
- **設定**:估算人數、排菜規則、菜商叫貨排程、供應商名稱
- **備份 / 還原 / 重設**

## 排菜規則

**飯菜日** = 主菜 3 道(豬 / 雞 / 魚)+ 蔬菜 2 道 + 蛋 1 道;**非飯菜日** = 非飯菜日卡池 1 道(設定可改)。不含湯。

類別依**主體食材**決定:只有豬、雞、魚為主的算主菜;南瓜燒肉片這類肉片只是配料的算蔬菜。

一定遵守(抽卡時):

| 規則 | 預設 |
|---|---|
| 停用的菜不會出現;候選菜不會自動抽到(只能手動選) | |
| 鎖定的菜不會被換掉 | |
| 同一天不會有兩道主體食材一樣的菜 | |
| 每天魚料理上限 | 1 道 |
| 每天炸物上限 | 1 道 |
| 同一種肉(豬 / 雞)每天上限 | 2 道 |
| 幾天內不重複 | 常用 7 天、輪替 14 天、非飯菜日 10 天 |

卡池不夠時會依序放寬「不重複天數」和「上限」,還是沒有就留空格並提醒。

盡量避免(抽卡時會挑搭配最好的一組,做不到就顯示 ⚠ 提醒):
- 深色醬汁超過 2 道、滷燒燉超過 2 道、同一種口味重複(例如兩道糖醋)
- 蔬菜沒有綠色青菜
- 葉菜(耐放度「低」)排在送貨後第 2、3 天

抽到的機率:常用比輪替高;越久沒排的菜越容易抽到;沒排過的菜不會被當成不受歡迎。

## 食材用量與叫貨

- 料理用量 = **30 人份的原料重量**(叫貨用的重量,已經包含經驗上的縮水,不會再乘縮水率)
- 叫貨量 = 用量 × 估算人數 ÷ 30 → 同一食材彙總 → 依叫貨級距無條件進位(預設半斤;盒、顆以 1 為單位)
- 1 台斤 = 600 公克
- 菜商排程(設定可改):

| 叫貨 | 送貨 | 涵蓋 |
|---|---|---|
| 星期一 | 星期二 | 二、三 |
| 星期三 | 星期四 | 四、五、六 |
| 星期六 | 星期日 | 日、一(星期一菜商不送貨) |

## 初始卡池

第一次打開 App 時的內容。**用量都是建議值,請依實際情況修改。**

- 狀態:你們提供的菜色先標「常用」或「輪替」;標「系統新增」的是我補的,請確認
- 南瓜燒肉、馬鈴薯燉肉、芋頭燒肉、水蓮炒肉絲依「主體食材」規則歸到蔬菜
- 品名有 ❓ 待確認的:豆菜(綠豆芽?)、杏菜苗、冬而、青龍、水血、馬薯、豆干(原單只有豆干絲)、白北魚

## 程式架構

| 檔案 | 內容 |
|---|---|
| `meal/src/main/assets/index.html` | 畫面(今日、菜單、叫貨、卡池、更多) |
| `meal/src/main/assets/logic.js` | 抽卡、搭配檢查、叫貨批次、用量計算、輸出文字(沒有畫面,可以單獨測試) |
| `meal/src/main/assets/seed.js` | 初始品項、卡池、設定 |
| `meal/src/main/java/.../MainActivity.kt` | 存檔、剪貼簿、傳到 LINE、返回鍵 |
| `tools/meal_test.js` | 核心邏輯測試(`node --test tools/meal_test.js`,每次編譯前執行) |
